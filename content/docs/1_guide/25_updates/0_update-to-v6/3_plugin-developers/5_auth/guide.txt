Title: Custom auth methods & challenges

----

Intro: Kirby 6 rebuilt authentication around two extension points: auth methods start a login, auth challenges confirm it. Both are now instance-based PHP classes that bring their own form for the Panel login view.

----

Text:

## Methods and challenges

A login in Kirby 6 has up to two steps:

1. An **auth method** starts the login. It either logs the user in directly or creates a challenge. The core login methods are `password`, `code` and `webauthn` (passkeys).
2. An **auth challenge** confirms the login, e.g. with a one-time code or a passkey. The core challenges are `email`, `totp` and `webauthn`. Challenges are used as second factor after a password, for passwordless logins with the `code` method and for password resets.

Plugins can add both. Kirby 5 already had the `authChallenges` extension, Kirby 6 adds `authMethods` and replaces the static challenge class with a new base class that brings its own form for the Panel login view.

The reference explains both in detail: (link: docs/reference/plugins/extensions/auth-methods text: auth methods), including the login view, entries in the security drawer and rate limiting with `Auth::guard()`, and (link: docs/reference/plugins/extensions/auth-challenges text: auth challenges).

## Migrating a Kirby 5 challenge

A custom challenge for Kirby 5 extends `Kirby\Cms\Auth\Challenge`. This class no longer exists, so the plugin breaks with a "class not found" error until you update it. Here is an SMS challenge for Kirby 5 and what changes in Kirby 6.

### Before: Kirby 5

```php "/site/plugins/acme-auth/classes/SmsChallenge.php"
<?php

namespace Acme\Auth;

use Kirby\Cms\Auth\Challenge;
use Kirby\Cms\User;
use Kirby\Toolkit\Str;

class SmsChallenge extends Challenge
{
    public static function isAvailable(User $user, string $mode): bool
    {
        return $user->content()->get('phone')->isNotEmpty();
    }

    public static function create(User $user, array $options): string
    {
        $code = Str::random(6, 'num');

        // your SMS provider's client
        Gateway::send(
            $user->content()->get('phone')->value(),
            'Your login code: ' . $code
        );

        // Kirby hashed the returned code and stored it in the session
        return $code;
    }

    // no verify(): the base class compared the input
    // with the hashed code from the session
}
```

```php "/site/plugins/acme-auth/index.php"
Kirby::plugin('acme/auth', [
    'authChallenges' => [
        'sms' => Acme\Auth\SmsChallenge::class
    ],
    'translations' => [
        'en' => [
            'login.code.placeholder.sms' => '000000',
            'login.code.text.sms'        => 'We sent a code to your phone.'
        ]
    ]
]);
```

### After: Kirby 6

The challenge extends `Kirby\Auth\Challenge` and is now created for a specific user and purpose:

- `isAvailable()`, `create()` and `verify()` are instance methods. Use `$this->user`, `$this->mode` and `$this->timeout` instead of the `$user`, `$mode` and `$options` arguments.
- `create()` returns a `Kirby\Auth\Pending` object instead of the code. Put the hashed code into `secret`, Kirby no longer hashes it for you. Its `public` data is sent to the browser before the login is complete.
- `verify()` is required and receives the user's input and the `Pending` object.
- `form()` returns the Vue component for the login view. Kirby 5 rendered the same generic code form for every challenge.
- If `isAvailable()` returns `true` for the `2fa` mode, the challenge counts as (link: docs/reference/plugins/extensions/auth-challenges#the-challenge-class__availability-means-set-up text: set up) and the user is asked for it after every password login.

You can find the same challenge for Kirby 6 with its form and translations in the (link: docs/reference/plugins/extensions/auth-challenges#example-codes-via-sms text: auth challenges reference).

## Replacing the login form

In Kirby 5, a plugin could replace the whole login form with the `login` extension of `window.panel.plugin()`. This extension has been removed in Kirby 6, together with the `<k-login-form>` and `<k-login-code-form>` components and the deprecated aliases `<k-login>` and `<k-login-code>`.

Write an auth method instead and return your form from its `form()` method. Your method then appears next to the core methods, and site developers decide in `auth.methods` whether it's the only one, the first one or an alternative.

Find all other changes to the auth system in the (link: releases/6/changelog#breaking-changes__auth text: changelog) and the (link: docs/guide/updates/update-to-v6/plugin-developers text: migration guide for plugin developers).
