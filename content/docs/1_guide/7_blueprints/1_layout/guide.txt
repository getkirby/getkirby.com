Title: Structuring blueprints
----

Intro: With blueprints you can create highly customized layouts that display the perfect interface for any type of data.

----

Text:

## Only fields

The most simple setup of a blueprint is a form with just a few fields. For this setup, you can add fields using the `fields` keyword, then add your fields underneath with proper indentation:

(image: fields.png)

```yaml
title: My blueprint

fields:
  headline:
    label: Headline
    type: text
  text:
    label: Text
    type: textarea
```

For more sophisticated setups, you can use columns and tabs to create nice layouts.

<info>
The `fields` keyword works on the top blueprint level like in the example above, and equally inside columns and tabs.
</info>

## More than input fields

Not every field collects content. Some display what is already there, and they are written exactly like any other field:

(image: stacked-fields.png alt: Outline of stacked fields in a single column layout)

Here are some examples:

(tabs…)

=== Multiple page lists

In this example we use two (link: docs/reference/panel/fields/pagelist text: `pagelist` fields) to separate drafts from published pages:

```yaml
title: My blueprint

fields:
  drafts:
    type: pagelist
    label: Drafts
    status: draft
  published:
    type: pagelist
    label: Published pages
    status: listed
```


=== Pages & files

In this example we have a (link: docs/reference/panel/fields/pagelist text: `pagelist`) and a (link: docs/reference/panel/fields/filelist text: `filelist`) below each other:

```yaml
title: My blueprint

fields:
  pages:
    type: pagelist
    label: Pages
  files:
    type: filelist
    label: Files
```

=== Mixed with input fields

Lists and input fields live in the same `fields` list and can be ordered freely:

```yaml
title: My blueprint

fields:
  pages:
    type: pagelist
    label: Pages
  text:
    type: text
  description:
    type: text
```

(…tabs)


## Columns

(image: columns.png)

A single stacked column like the above can sometimes be useful, in many cases you will, however, want to give more structure to your layout. That's where `columns` come into play.

A column holds fields of any type, in any order.


### Defining columns

Column definitions start with the `columns` keyword, followed by the individual column definitions. Columns can be defined in two ways:

(tabs…)

=== Named columns

```yaml
title: My blueprint

columns:
  left:
    width: 2/3
    fields:
      # fields in the left column
  right:
    width: 1/3
    fields:
      # fields in the right column
```

<info>
You have to use named columns if you want to (link: docs/guide/blueprints/extending-blueprints text: extend columns).
</info>

=== Unnamed columns

```yaml
title: My blueprint

columns:
  - width: 2/3
    fields:
      # fields in the left column
  - width: 1/3
    fields:
      # fields in the right column
```
(…tabs)


The following widths are available when defining columns:
`1/2`, `1/3`, `1/4`, `2/3`, `2/4`, `3/4`

### Adding fields to columns

Just like a blueprint itself, a column contains fields:

```yaml
title: My blueprint

columns:
  - width: 2/3
    fields:
      subtitle:
        type: text
      blocks:
        type: blocks
  - width: 1/3
    fields:
      published:
        type: date
      author:
        type: userpicker
        max: 1
```

A column that displays existing content works the same way. Here the main column holds a form and the sidebar lists the page's subpages and files:

```yaml
title: My blueprint

columns:
  # main
  main:
    width: 2/3
    fields:
      headline:
        label: Headline
        type: text
      text:
        label: Text
        type: textarea

  # sidebar
  sidebar:
    width: 1/3
    fields:

      # a list of subpages
      pages:
        type: pagelist
        label: Subpages

      # a list of files
      files:
        type: filelist
        label: Files
```


(image: sidebar-right.png caption: Two-column layout with sidebar on the right (page and file lists) and form fields on the left.)


You can probably already see how flexible this is. By slightly changing the columns, we can change the interface drastically.



### Sidebar on the left

```yaml
title: My blueprint

columns:

  # sidebar
  sidebar:
    width: 1/3
    fields:

      # a list of subpages
      pages:
        type: pagelist
        label: Subpages

      # a list of files
      files:
        type: filelist
        label: Files

  # main
  main:
    width: 2/3
    fields:
      headline:
        label: Headline
        type: text
      text:
        label: Text
        type: textarea
```
(image: sidebar-left.png caption: Two-column layout with sidebar on the left (page and file lists) and form fields on the right.)

### Two Sidebars

```yaml
title: My blueprint

columns:

  # sidebar left
  left:
    width: 1/4
    fields:

      # a list of subpages
      pages:
        type: pagelist
        label: Subpages
        template: default

  # main
  main:
    width: 1/2
    fields:

      # a simple form
      headline:
        label: Headline
        type: text
      text:
        label: Text
        type: textarea
  # sidebar right
  right:
    width: 1/4
    fields:
      # a list of files
      files:
        type: filelist
        label: Files
```

(image: sidebar-both.png caption: Three-column layout with sidebars on the right (page list) and on the left (file list) and form fields in the middle.)

### Sticky columns

You can make an entire column sticky. This can be handy for a setup with a smaller sidebar that should always be available, even when you scroll.

```yaml
columns:
  - width: 1/3
    sticky: true
    fields:
      # fields in the sticky column
```

## Adapt all to your needs

(image: columns-complex.png)

Kirby gives you the flexibility to set up the (glossary: Panel) so that it adapts to the needs of every single page/template. Use the layout possibilities to create the structure that works best for you:

```yaml
title: My blueprint

columns:
  gallery:
    width: 1/1
    fields:
      gallery:
        type: filelist
        layout: card
        ...

  review:
    width: 1/2
    fields:
      drafts:
        type: pagelist
        status: draft
        ...
      review:
        type: pagelist
        status: unlisted
        ...

  published:
    width: 1/2
    fields:
      published:
        type: pagelist
        status: listed
        ...
```


If this isn't yet enough ways and space for you to structure your fields, move on with…

## Tabs

When your blueprints get more complex, splitting up your view into multiple tabs helps to keep them organized. Tabs are basically wrappers around regular blueprint layouts. Check out (link: #columns text: how to create layouts) before you get started with tabs.

(image: tabs.png)

Like the blueprint itself, a tab can contain

- only fields
- one or more fields
- columns with fields

### Defining tabs

 A tab definition has three options:

- label
- columns
- icon

The icon is optional. Please check out the (link: docs/reference/panel/icons text: list of available icons). You can also use an emoji by pasting it directly into the blueprint.

```yaml
title: My blueprint

tabs:
  content:
    label: Content
    icon: text
    columns:
      # layout
  seo:
    label: SEO
    icon: search
    columns:
      # layout
```


(image: sidebar-right-and-tabs.png)

### Full example

```yaml
title: My blueprint

tabs:

  # content tab
  content:
    label: Content
    icon: text
    columns:

      # main
      main:
        width: 2/3
        fields:

          # a simple form
          headline:
            label: Headline
            type: text
          text:
            label: Text
            type: textarea
      # sidebar
      sidebar:
        width: 1/3
        fields:

          # a list of subpages
          pages:
            type: pagelist
            label: Subpages

          # a list of files
          files:
            type: filelist
            label: Files

  # seo tab
  seo:
    label: SEO
    icon: search
    fields:
      seoTitle:
        label: SEO Title
        type: text
      seoDescription:
        label: SEO Description
        type: text
```
