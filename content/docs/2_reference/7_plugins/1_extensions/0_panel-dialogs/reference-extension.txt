Title: Panel dialogs

----

Text:

As part of your (link: docs/reference/plugins/extensions/panel-areas text: Panel area extension), you can also define custom dialogs for the Panel as well as extend or modify the Panel's default dialogs.

## Dialog definition

Dialogs are defined as a part of areas. The key of a dialog is its name and, unless you set a `pattern`, also its route. A dialog has two handlers:

- `load` is called when the dialog opens (a `GET` request to `/panel/dialogs/{pattern}`). It returns the dialog component to use and its props, e.g. the fields and values for a form dialog.
- `submit` is called when the dialog is submitted (a `POST` request to the same route) and returns the result.

```php "/site/plugins/todos/index.php"
<?php

Kirby::plugin(
  name: 'yourname/todos',
  extends: [
    'areas' => [
      'todos' => fn () => [
        // ... other code for the custom Panel area
        'dialogs' => [
          'todo.create' => [
            'pattern' => 'todos/create',
            'load'    => fn () => [
              'component' => 'k-form-dialog',
              'props'     => [
                'fields' => [
                  'text' => ['label' => 'Todo', 'type' => 'text']
                ]
              ]
            ],
            'submit'  => function () {
              $text = kirby()->request()->get('text');
              // create the todo
              return true;
            }
          ]
        ]
      ]
    ]
  ]
);
```

Placeholders in the pattern, e.g. `todos/(:any)/update`, are passed to both handlers as arguments.

## Dialog components

The Panel comes with these dialog components:

| Component | Usage |
| --- | --- |
| (link: https://lab.getkirby.com/public/lab/docs/k-form-dialog text: `k-form-dialog`) | For dialogs with form fields (`fields`, `value`) |
| (link: https://lab.getkirby.com/public/lab/docs/k-remove-dialog text: `k-remove-dialog`) | To confirm deleting items |
| (link: https://lab.getkirby.com/public/lab/docs/k-text-dialog text: `k-text-dialog`) | For dialogs with a text message |
| (link: https://lab.getkirby.com/public/lab/docs/k-error-dialog text: `k-error-dialog`) | For detailed error messages |

All of them accept a `text`, a `size` and the `submitButton` and `cancelButton` props. Your own dialog components work the same way: return their name as `component` and their props in `props`.

The `text` is escaped unless it is (link: docs/guide/plugins/panel#trusted-html text: trusted HTML). To show HTML, pass an `HtmlString` object instead of a plain string:

```php
use Kirby\Toolkit\HtmlString;

return [
  'component' => 'k-remove-dialog',
  'props'     => [
    'text' => HtmlString::translate(
      'Do you really want to delete <strong>{text}</strong>?',
      ['text' => $todo['text']]
    )
  ]
];
```

### Dialog objects

Instead of an array, `load` can return one of the dialog objects from the `Kirby\Panel\Ui\Dialog` namespace: `FormDialog`, `RemoveDialog`, `TextDialog` and `ErrorDialog`. They come with sensible defaults, e.g. the `medium` size or the trash icon and negative theme for the submit button of a `RemoveDialog`. All named arguments become props:

```php
use Kirby\Panel\Ui\Dialog\FormDialog;

'load' => fn () => new FormDialog(
  fields: [
    'text' => ['label' => 'Todo', 'type' => 'text']
  ]
)
```

For your own dialog components, you can create your own dialog classes as well, by extending `Kirby\Panel\Ui\Dialog` or one of the classes above, e.g. `TextDialog`.

## Submit results

What `submit` returns decides what happens next:

- `true` closes the dialog.
- An array closes the dialog and can trigger an event (`'event' => 'todo.create'`, with optional `'data'`), redirect to another Panel URL (`'redirect' => 'todos'`) or skip the reload of the current view (`'reload' => false`).
- `null` or `false` is interpreted as "not found" and shows an error.
- An exception shows its message as an error in the dialog.

To redirect from anywhere in your code, call `Panel::go('some/path')`.

## Controller classes

Instead of `load` and `submit` closures, you can handle a dialog with a controller class. Pass its class name as `action`:

```php
'dialogs' => [
  'todo.update' => [
    'pattern' => 'todos/(:any)/update',
    'action'  => TodoUpdateDialogController::class
  ]
]
```

The class extends `Kirby\Panel\Controller\DialogController`. Its `load()` method returns the dialog, and `submit()` handles the submission (by default, it returns `true`).

When the route is called, Kirby creates the controller with the placeholders of the route pattern. If the class has a static `factory()` method, Kirby calls it, otherwise the constructor. The factory is the place to turn the URL arguments into the objects your controller works with:

```php "/site/plugins/todos/classes/TodoUpdateDialogController.php"
<?php

use Kirby\Panel\Controller\DialogController;
use Kirby\Panel\Ui\Dialog\FormDialog;

class TodoUpdateDialogController extends DialogController
{
  public function __construct(
    public string $id,
    public array $todo
  ) {
    parent::__construct();
  }

  // called with the (:any) part of `todos/(:any)/update`
  public static function factory(string $id): static
  {
    return new static(id: $id, todo: todo($id));
  }

  public function load(): FormDialog
  {
    return new FormDialog(
      fields: [
        'text' => ['label' => 'Todo', 'type' => 'text']
      ],
      value: $this->todo
    );
  }

  public function submit(): bool
  {
    // save the todo with $this->request->get('text')
    return true;
  }
}
```

You can also create the controller yourself in a closure, e.g. to pass extra arguments:

```php
'action' => fn (string $id) => new TodoUpdateDialogController(
  id: $id,
  todo: todo($id)
)
```

## Extending dialogs

You can also replace or extend the Panel's core dialogs. Kirby merges your definition into the core definition, so you only define what you want to change:

```php "/site/plugins/custom-dialog/index.php"
<?php

Kirby::plugin(
  name: 'custom/dialog',
  extends: [
    'areas' => [
      'site' => fn () => [
        'dialogs' => [
          'page.changeStatus' => [
            'load' => function (string $id) {
              // custom dialog setup
            },
            'submit' => function (string $id) {
              // custom submit action
            }
          ]
        ]
      ]
    ]
  ]
);
```

`load` and `submit` closures take precedence over the core controller: you can replace only `load` and keep the core `submit`, replace both, or replace the whole controller with `action`. To remove a core dialog, set it to `false`.

### Reusing core functionalities

All core dialogs are handled by controller classes, which you can call to fall back to Kirby's core behavior:

```php "/site/plugins/custom-dialog/index.php"
<?php

use Kirby\Cms\Find;
use Kirby\Panel\Controller\Dialog\PageChangeStatusDialogController;

Kirby::plugin(
  name: 'custom/dialog',
  extends: [
    'areas' => [
      'site' => fn () => [
        'dialogs' => [
          'page.changeStatus' => [
            'load' => function (string $id) {
              if (Find::page($id)->id() === 'blog') {
                // return a custom dialog for the blog
              }

              return PageChangeStatusDialogController::factory($id)->load();
            }
          ]
        ]
      ]
    ]
  ]
);
```

You find the names of all core dialogs in the area definitions in (link: https://github.com/getkirby/kirby/tree/main/config/areas text: `/kirby/config/areas`) and their controllers in (link: https://github.com/getkirby/kirby/tree/main/src/Panel/Controller/Dialog text: `/kirby/src/Panel/Controller/Dialog`).
