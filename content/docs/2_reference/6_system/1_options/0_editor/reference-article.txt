Intro: Sets the code editor for links in error messages

----

Text:

When your debug mode is enabled, you can set your code editor to quickly open the file in which the error appeared:

```php "/site/config/config.php"
return [
	'debug'  => true,
	'editor' => 'vscode'
];
```

On the Whoops error page of your site, a click on the file opens it at the right line in your editor:

(video: error.mp4)

| - | - |
| `antigravity` | Antigravity |
| `atom` | Atom |
| `cursor` | Cursor |
| `emacs` | Emacs |
| `espresso` | Espresso |
| `fleet` | Fleet |
| `idea` | IntelliJ IDEA |
| `kiro` | Kiro |
| `macvim` | MacVim |
| `neovim` | Neovim |
| `netbeans` | NetBeans |
| `nova` | Nova |
| `phpstorm` | PhpStorm |
| `sublime` | Sublime Text |
| `textmate` | TextMate |
| `trae` | Trae |
| `vscode` | Visual Studio Code |
| `vscodium` | VSCodium |
| `windsurf` | Windsurf |
| `xdebug` | The link format from the `xdebug.file_link_format` setting of Xdebug |
| `zed` | Zed |

<info>
`xdebug` is only available if `xdebug.file_link_format` is set in your `php.ini`.
</info>

<alert>
Make sure to disable `debug` mode in production! Displaying PHP errors on a public server can be a serious security risk:

- Error messages are displayed with detailed information about the code structure (e.g. file path, class, method)
- With Whoops enabled, there will be even more detailed information about the code structure

In a production environment, always log errors to your PHP error logs.
</alert>
