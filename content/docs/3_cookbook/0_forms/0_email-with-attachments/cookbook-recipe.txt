Text:

This recipe extends the (link: docs/cookbook/forms/basic-contact-form text: basic contact form) example, but this time the user can attach some files. As an example we use a job application form.

To follow this example, your content structure should look like this:

```filesystem
content/
    1_jobs/
        20260901_job-a/
            job.txt
        20260915_job-b/
            job.txt
        20261001_job-c/
            job.txt
        jobs.txt
    2_applications/
        applications.txt
    success/
        success.txt
    ...
```

We also need the following files:

- an (glossary: template text: applications template) with the form snippet
- the application form (glossary: snippet text: snippet)
- the (glossary: controller text: controller) that handles the form logic
- a plain text or an HTML email (glossary: template text: template)
- two templates for the `jobs` overview page and its subpages (see the demo download below)

The workflow is like this:

When users visit a job page, they can click on a link that leads to the application form. The link contains the reference that is then prefilled in the form's reference field. Users can however change this field input if they decide they would rather apply for another job (or if they visit the `applications` page directly).

<info>
With this setup, we keep the application process away from the job listings and can put it behind a login wall if needed. Instead of handling the applications on a general applications form like in this example, you could also show the form on every job page.
</info>

## The job application page

(link: docs/guide/content/creating-pages text: Create) an `applications` page with an `applications.txt` content file. For our means, a title and a short intro text are all we need, the rest is up to you.

For use in the Panel, you can create a (glossary: blueprint text: blueprint) for the page. We will skip this step here.

## The `applications.php` template

The template contains the form and will display error messages if something goes wrong. To keep the `applications.php` template clean, we include the form as a snippet.

The error messages can contain the names of the uploaded files, so we escape them before we output them.


```php "/site/templates/applications.php"
<?php snippet('header') ?>

<main>
  <article class="applications">
    <header class="application-header intro">
      <h1><?= $page->title() ?></h1>
    </header>

    <div class="text">
      <?= $page->text()->kt() ?>
    </div>

    <?php
    // if the form input is not valid, show a list of alerts
    if ($alerts): ?>
    <div class="alert">
      <ul>
        <?php foreach ($alerts as $message): ?>
        <li><?= esc($message) ?></li>
        <?php endforeach ?>
      </ul>
    </div>
    <?php endif ?>

    <?php snippet('application-form', ['data' => $data]) ?>
  </article>
</main>

<?php snippet('footer') ?>
```

## The form snippet

```php "/site/snippets/application-form.php"
<form class="application-form" action="<?= $page->url() ?>" method="POST" enctype="multipart/form-data">

  <div class="form-element">
    <label for="name">Name <abbr title="required">*</abbr></label>
    <input type="text" id="name" name="name" value="<?= esc($data['name'] ?? '', 'attr') ?>" required>
  </div>

  <div class="form-element">
    <label for="email">Email <abbr title="required">*</abbr></label>
    <input type="email" id="email" name="email" value="<?= esc($data['email'] ?? '', 'attr') ?>" required>
  </div>

  <div class="form-element">
    <label for="reference">Job reference number <abbr title="required">*</abbr></label>
    <input type="text" id="reference" name="reference" value="<?= esc($data['reference'] ?? get('reference', ''), 'attr') ?>" required>
  </div>

  <div class="form-element">
    <label for="message">Message <abbr title="required">*</abbr></label>
    <textarea id="message" name="message" required><?= esc($data['message'] ?? '') ?></textarea>
  </div>

  <div class="form-element">
    <label for="file">
      Your documents <abbr title="required">*</abbr>
      <span class="help">Up to 3 PDF files, max. 2 MB each</span>
    </label>
    <input type="file" id="file" name="file[]" accept="application/pdf" multiple required>
  </div>

  <div class="honey">
    <label for="website">If you are a human, leave this field empty</label>
    <input type="url" id="website" name="website" tabindex="-1" autocomplete="off">
  </div>

  <input type="hidden" name="csrf" value="<?= csrf() ?>">
  <input class="application-button" type="submit" name="submit" value="Apply">

</form>
```

The form snippet contains some form fields (`name`, `email`, `reference`, `message`, `file`), a honeypot field to ensure a minimum level of spam bot protection and a hidden field with a (link: docs/reference/templates/helpers/csrf text: CSRF token), which makes sure that the request was sent from our form.

The honeypot field needs to be positioned off the screen via CSS. Therefore add these styles to your stylesheet (you can change the class and styling).

```css
.honey {
    position: absolute;
    left: -9999px;
}
```

Note that since we want to upload files, we have to set the encoding type attribute to `enctype="multipart/form-data"`. The `accept` attribute of the file input only offers PDF files in the file dialog of the browser. It's a convenience for the user, not a security measure, so we check the files again in the controller.

Because the `$data` and `$alerts` variables get controlled by user input, it is important to escape the text to protect against (link: docs/guide/templates/escaping text: XSS vulnerabilities).

## The controller

The controller handles our form validation logic.

```php "/site/controllers/applications.php"
<?php

use Kirby\Filesystem\Dir;
use Kirby\Filesystem\F;
use Kirby\Filesystem\Mime;
use Kirby\Toolkit\Str;

return function ($kirby, $page) {

    // if the form has been submitted…
    if ($kirby->request()->is('POST') && get('submit')) {

        // check the honeypot and exit if it has been filled in
        if (empty(get('website')) === false) {
            go($page->url());
        }

        $alerts = [];
        $data   = [
            'name'      => get('name'),
            'email'     => get('email'),
            'reference' => get('reference'),
            'message'   => get('message')
        ];

        // check the CSRF token to make sure the request came from our form
        if (csrf(get('csrf')) !== true) {
            return [
                'alerts' => ['Your session has expired. Please submit the form again.'],
                'data'   => $data
            ];
        }

        $rules = [
            'name'      => ['required', 'min' => 3],
            'email'     => ['required', 'email'],
            'reference' => ['required', 'in' => [page('jobs')->children()->listed()->pluck('reference', ',')]],
            'message'   => ['required', 'min' => 10, 'max' => 3000],
        ];

        $messages = [
            'name'      => 'Please enter a valid name.',
            'email'     => 'Please enter a valid email address.',
            'reference' => 'Please enter a valid reference.',
            'message'   => 'Please enter a text between 10 and 3000 characters.'
        ];

        // some of the data is invalid
        if ($invalid = invalid($data, $rules, $messages)) {
            $alerts = $invalid;
        }

        // get the uploads
        $uploads = $kirby->request()->files()->get('file') ?? [];

        // we want no more than 3 files
        if (count($uploads) > 3) {
            $alerts[] = 'You may only upload up to 3 files.';
        }

        // valid uploads are moved to a temporary folder of their
        // own, so they can be attached with their original name
        $folder      = sys_get_temp_dir() . '/application-' . Str::random(16);
        $attachments = [];

        // loop through uploads and check if they are valid
        foreach ($uploads as $upload) {
            // make sure the user uploads at least one file
            if ($upload['error'] === UPLOAD_ERR_NO_FILE) {
                $alerts[] = 'You have to attach at least one file.';
            // make sure there are no other errors
            } elseif ($upload['error'] !== UPLOAD_ERR_OK) {
                $alerts[] = 'The file could not be uploaded.';
            // make sure the file is not larger than 2 MB…
            } elseif ($upload['size'] > 2000000) {
                $alerts[] = $upload['name'] . ' is larger than 2 MB.';
            // …and the file is a PDF: we check the file itself,
            // because the type sent by the browser can be faked
            } elseif (Mime::type($upload['tmp_name']) !== 'application/pdf') {
                $alerts[] = $upload['name'] . ' is not a PDF.';
            // all valid, move the file with a sanitized name
            } else {
                Dir::make($folder);

                $file = $folder . '/' . F::safeName($upload['name']);

                if (move_uploaded_file($upload['tmp_name'], $file) === true) {
                    $attachments[] = $file;
                }
            }
        }

        // the data is fine, let's send the email with attachments
        if (empty($alerts) === true) {
            try {
                $kirby->email([
                    'template'    => 'email',
                    'from'        => 'yourcontactform@yourcompany.com',
                    'replyTo'     => $data['email'],
                    'to'          => 'you@yourcompany.com',
                    'subject'     => $data['name'] . ' applied for job ' . $data['reference'],
                    'data'        => $data,
                    'attachments' => $attachments
                ]);
            } catch (Exception $error) {
                // we only display a general error message, for debugging use `$error->getMessage()`
                $alerts[] = 'The email could not be sent.';
            }
        }

        // the files are no longer needed, whether the email was sent or not
        Dir::remove($folder);

        // no exception occurred, let's send a success message
        if (empty($alerts) === true) {
            // store reference and name in the session for use on the success page
            $kirby->session()->set([
                'reference' => $data['reference'],
                'name'      => $data['name']
            ]);

            // redirect to the success page
            go('success');
        }
    }

    // return data to template
    return [
        'alerts' => $alerts ?? null,
        'data'   => $data ?? false,
    ];
};
```

Let's go through the most important steps here in detail. The rest is commented in the code snippet.

### Validate input data

In our controller, the form evaluation starts once we receive a `POST` request. First, we check if a bot got trapped in our honeypot. In this case, we send it back to the page and stop script execution.

Then we check the CSRF token. If it isn't valid, e.g. because the session has expired, we stop right away and ask the user to submit the form again.

Next, we check if all form fields have been filled in according to our validation rules using the [`invalid()` helper](/docs/reference/templates/helpers/invalid):

```php
$rules = [
    'name'      => ['required', 'min' => 3],
    'email'     => ['required', 'email'],
    'reference' => ['required', 'in' => [page('jobs')->children()->listed()->pluck('reference', ',')]],
    'message'   => ['required', 'min' => 10, 'max' => 3000],
];
```

- All fields are required and must be filled out.
- The `email` field must contain a valid email address.
- The `name` field must be at least 3 characters long.
- The `message` field must be between 10 and 3000 characters.
- The `reference` field must be a valid reference from one of the `jobs` subpages

You can change these rules depending on the type of data you want to obtain and use (link: docs/reference/system/validators text: Kirby's validators) or (link: docs/reference/plugins/extensions/validators text: your own custom validators) to make sure you get the desired data.

### Validate uploaded files

We then handle the file submissions. We fetch the uploaded file(s) with `$kirby->request()->files()->get('file')`, where `file` is the name of our input field. If the user tries to upload more than 3 files, we add a message to the `$alerts` array.

```php
// get the uploads
$uploads = $kirby->request()->files()->get('file') ?? [];

// we want no more than 3 files
if (count($uploads) > 3) {
    $alerts[] = 'You may only upload up to 3 files.';
}
```

Then we loop through the files array and check for each upload if it is valid:

- We check the `$upload['error']` value to make sure that we have at least one upload and no other error occurred
- We check the file size to make sure that the file is not larger than allowed
- We check if the upload is a PDF. The type in `$upload['type']` is sent by the browser and can be faked, so we let (link: docs/reference/objects/filesystem/mime/type text: `Mime::type()`) detect the type from the file itself.

As the last step in this loop, we move each valid upload with a sanitized version of its original name into a temporary folder of its own. This way, the files are attached with their original names, and files with the same name from two simultaneous applications can't overwrite each other.

```php
// valid uploads are moved to a temporary folder of their
// own, so they can be attached with their original name
$folder      = sys_get_temp_dir() . '/application-' . Str::random(16);
$attachments = [];

// loop through uploads and check if they are valid
foreach ($uploads as $upload) {
    // make sure the user uploads at least one file
    if ($upload['error'] === UPLOAD_ERR_NO_FILE) {
        $alerts[] = 'You have to attach at least one file.';
    // make sure there are no other errors
    } elseif ($upload['error'] !== UPLOAD_ERR_OK) {
        $alerts[] = 'The file could not be uploaded.';
    // make sure the file is not larger than 2 MB…
    } elseif ($upload['size'] > 2000000) {
        $alerts[] = $upload['name'] . ' is larger than 2 MB.';
    // …and the file is a PDF: we check the file itself,
    // because the type sent by the browser can be faked
    } elseif (Mime::type($upload['tmp_name']) !== 'application/pdf') {
        $alerts[] = $upload['name'] . ' is not a PDF.';
    // all valid, move the file with a sanitized name
    } else {
        Dir::make($folder);

        $file = $folder . '/' . F::safeName($upload['name']);

        if (move_uploaded_file($upload['tmp_name'], $file) === true) {
            $attachments[] = $file;
        }
    }
}
```

## Send email

If all went well, we try to send the email together with the file attachments in a `try - catch` block. We pass the form data as it is: the subject and the plain text email don't need escaping, and the HTML template escapes the values itself.

```php
// the data is fine, let's send the email with attachments
if (empty($alerts) === true) {
    try {
        $kirby->email([
            'template'    => 'email',
            'from'        => 'yourcontactform@yourcompany.com',
            'replyTo'     => $data['email'],
            'to'          => 'you@yourcompany.com',
            'subject'     => $data['name'] . ' applied for job ' . $data['reference'],
            'data'        => $data,
            'attachments' => $attachments
        ]);
    } catch (Exception $error) {
        // we only display a general error message, for debugging use `$error->getMessage()`
        $alerts[] = 'The email could not be sent.';
    }
}

// the files are no longer needed, whether the email was sent or not
Dir::remove($folder);
```

Once the email has been sent, we don't need the uploaded files anymore, so we remove the temporary folder. We also remove it if something went wrong, so that no applications stay behind on the server.

If the email was sent, we store the user's name and the job reference number in the session and redirect the user to the `success` page.

```php
// no exception occurred, let's send a success message
if (empty($alerts) === true) {
    // store reference and name in the session for use on the success page
    $kirby->session()->set([
        'reference' => $data['reference'],
        'name'      => $data['name']
    ]);

    // redirect to the success page
    go('success');
}
```

## The email templates

In our [`$kirby->email()` method](/docs/reference/objects/kirby/email) above, we defined a template we want to use to send the email. In this example, we use a template called `email`, which is stored in `/site/templates/emails`.

We can use both a plain text template and/or an HTML version. You can read more about this in the (link: docs/guide/emails text: email guide).

Here are the two email templates:

### The plain text template

The plain text template gets the extension `.php`.

```php "/site/templates/emails/email.php"
Hello,

<?= $message ?>


Yours sincerely,
<?= $name ?>
```

### The HTML template

The HTML template gets the extension `html.php`.

```php "/site/templates/emails/email.html.php"
<p>Hello,</p>

<p><?= nl2br(esc($message)) ?></p>

<p>
  Yours sincerely,<br>
  <?= esc($name) ?>
</p>
```

Both templates are kept very simple. Kirby provides the values of the `data` array as variables in the email templates: `$name`, `$email`, `$reference` and `$message`. The HTML template escapes them, because they come from user input. You can of course change the templates to your liking.

## The success page

The success content file contains placeholders for the applicant's name and the job reference number:

```kirbycontent
Title: Success
\----
Text:

Hello {{ name }},
Thank you for applying as **{{ job }}**.

We will be in touch shortly.

Your HR department
```

### A plugin to replace the placeholders

In the plugin, we replace the `name` and `job` placeholders in the text with the data we stored in the session. The hook runs for every text that is parsed as KirbyText, so we only touch texts that contain placeholders. The values come from user input, so we escape them.

```php "/site/plugins/applications/index.php"
<?php

use Kirby\Cms\App as Kirby;
use Kirby\Toolkit\Str;

Kirby::plugin(
    name: 'jobkit/application',
    extends: [
        'hooks' => [
            'kirbytags:after' => function (string|null $text, array $data, array $options) {
                // only touch texts that contain our placeholders
                if ($text === null || Str::contains($text, '{{') === false) {
                    return $text;
                }

                $session = kirby()->session();

                if ($reference = $session->get('reference')) {
                    if ($job = page('jobs')->children()->findBy('reference', $reference)) {
                        $title = $job->title() . ' (reference ' . $reference . ')';
                    }
                }

                return Str::template($text, [
                    'job'  => esc($title ?? ''),
                    'name' => esc($session->get('name') ?? '')
                ]);
            }
        ],
    ]
);
```
