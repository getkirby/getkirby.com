In this recipe, we will create a custom Panel field that displays a list of links with an icon, a title and a description. This is what it will look like once we are ready:

(image: custom-field.webp)

<info>
For the purposes of this recipe, we assume you have read the (link: docs/guide/plugins/panel text: Panel plugins guide) on how to get started with our Panel plugin bundler (link: https://github.com/johannschopplich/kirbyup text: kirbyup).

You can install the (link: https://github.com/getkirby/pluginkit/tree/step-3-panel text: Pluginkit) as a basis or create the file structure we need manually, that's up to you. Also, it doesn't matter if you use the Plainkit or the Starterkit as a starting point.
</info>

## Getting started

Please read the (link: docs/reference/plugins/extensions/fields text: chapter about custom fields in the reference) before starting with this example.

Let's get started with the plugin folder, we'll call it `/linkfield`. Inside this folder, we create a `package.json` file which is needed so that kirbyup knows what to do.

```json "/site/plugins/linkfield/package.json"
{
  "name": "linkfield",
  "private": true,
  "scripts": {
    "dev": "npx -y kirbyup src/index.js --watch",
    "build": "npx -y kirbyup src/index.js"
  }
}
```

This will take care of compiling our source files into an `index.js` file in the root of our `linkfield` plugin folder.

## Register the field: PHP part

Every field in Kirby is a PHP class. Our field only displays links and doesn't store anything in the content file, so its class extends Kirby's `DisplayField` class, which already comes with the `label` and `help` options. We add two more options: a `layout` and the `links` themselves. These are the options we can later define in the blueprint for the field.

```php "/site/plugins/linkfield/src/LinksField.php"
<?php

namespace GetKirby\LinkField;

use Kirby\Form\Field\DisplayField;
use Kirby\Reflection\Attributes\Prop;

class LinksField extends DisplayField
{
	/**
	 * Layout of the links: `list` or `cards`
	 */
	#[Prop]
	protected string $layout = 'list';

	/**
	 * The links to display
	 */
	#[Prop]
	protected array $links = [];
}
```

Each option is a typed property with the `#[Prop]` attribute. Its default value is used, if the option isn't set in the blueprint. Kirby sends all options to the Vue component of the field automatically.

We also need an `index.php` file that contains the Kirby plugin wrapper, in which we load the class and register it as `links` field.

```php "/site/plugins/linkfield/index.php"
<?php

use GetKirby\LinkField\LinksField;

F::loadClasses([
	'getkirby\\linkfield\\linksfield' => 'src/LinksField.php'
], __DIR__);

Kirby::plugin(
	name: 'getkirby/linkfield',
	extends: [
		'fields' => [
			'links' => LinksField::class
		]
	]
);
```

<info>
We put the class into its own file in a `/src` folder. This keeps the `index.php` short and gives you an idea of how to structure the files of more complex plugins. Read more about it in (link: docs/guide/plugins/structure text: Structuring your plugin code).
</info>

## Register the field: Vue part

Our new field also needs an `index.js` in which we register the field for the Vue part of the plugin.

```js "/site/plugins/linkfield/src/index.js"
import Links from "./components/fields/Links.vue";

panel.plugin("getkirby/linkfield", {
  fields: {
    links: Links
  }
});
```

Inside this file, we import the `Links.vue` component and assign this component to the `links` field. The `Links.vue` is stored inside a fields subfolder. This is not a required folder structure, but it makes sense to start using such subfolders for your components once you work with different types of components (fields, views, etc.)

## Set up the field component

Finally, we need the `Links.vue` component that contains the template for the field. The options from the PHP class arrive as props, so we declare them in the `props` object of the component:

```html "/site/plugins/linkfield/src/components/fields/Links.vue"
<template>
  <k-field :label="label" class="k-links-field">
    <k-collection :items="links" :layout="layout" />
  </k-field>
</template>

<script>
export default {
  inheritAttrs: false,
  props: {
    label: String,
    layout: String,
    links: Array
  }
};
</script>
```

Kirby makes this really easy for us by providing default components we can reuse all over the place. The `k-field` component takes care of the label. And the `k-collection` component makes it easy to switch between the cards and list layouts. All we have to do is bind our data to the `:items` property and our `layout` to the `:layout` property.

Kirby passes a few more props to every field, like `name`, `type` or `width`. `inheritAttrs: false` keeps the props our component doesn't declare from ending up as HTML attributes of our field.

At this point, we are ready to run…

```
npm run dev
```

…in the `linkfield` folder to compile our code into the main `index.js`.

## Set up the field in the blueprint

If this went smoothly, we are ready to use the field in a blueprint, e.g. `site.yml`:

```yaml "/site/blueprints/site.yml"
title: Site

fields:
  links:
    type: links
    label: Getting started
```

If we now open the Panel start page, we see the label of our field, but no links yet, because we haven't defined any.

## The blueprint with the final field definition

Finally, let's add the links we want to show in the field to the field definition. Each link uses the keys the `k-collection` component expects for its items: a `text`, an `info`, the `link` with its `target` and an `image`, for which we use a white icon on a black background in a 3/2 ratio.

```yaml "/site/blueprints/site.yml"
title: Site

fields:
  links:
    type: links
    label: Getting started
    layout: cards
    links:
      - text: Guide
        info: Get an overview of all the cool things you can do with Kirby
        link: https://getkirby.com/docs/guide
        target: _blank
        image:
          icon: book
          back: black
          color: white
          ratio: 3/2
      - text: Cookbook
        info: Yummy step by step recipes for all sorts of usage tastes
        link: https://getkirby.com/docs/cookbook
        target: _blank
        image:
          icon: palette
          back: black
          color: white
          ratio: 3/2
      - text: Reference
        info: Discover Kirby's API in all detail
        link: https://getkirby.com/docs/reference
        target: _blank
        image:
          icon: list-bullet
          back: black
          color: white
          ratio: 3/2
      - text: Plugins
        info: Find plugins to extend Kirby's core functionality and make the most of your site
        link: https://plugins.getkirby.com
        target: _blank
        image:
          icon: box
          back: black
          color: white
          ratio: 3/2
      - text: Forum
        info: Meet Kirby's lovely community and get help whenever you get stuck
        link: https://forum.getkirby.com
        target: _blank
        image:
          icon: users
          back: black
          color: white
          ratio: 3/2
```

Change the layout to `list` in the blueprint to see how your field is now displayed as a list.

## Building the plugin

Once you are happy with your plugin, you can create minified and optimized versions of the `index.js` and `index.css` (if you have added custom styles) with…

```
npm run build
```

## Final folder structure

```filesystem
linkfield/
  src/
    components/
      fields/
        Links.vue
    index.js
    LinksField.php
  index.js
  index.php
  package.json
```

## Where to go from here

This is a very basic example that should still have given you an understanding of how the different parts play together and enable you to set up your first custom fields for your clients. The data to fill this field can in fact come from anywhere: instead of the blueprint, the PHP class could load it from a database, an API or whatever you see fit. And you probably don't just want to display stuff, but add actions to each item etc.

You don't have to use the components Kirby provides, either, but can come up with your own markup and design. The possibilities are pretty much endless.
