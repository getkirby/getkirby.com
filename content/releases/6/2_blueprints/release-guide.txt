Title: Simpler blueprints

----

Subtitle: Less nesting, one concept: fields

----

Teaser:

Blueprints in Kirby 6 are a lot easier to handle: they need less nesting and fewer concepts. Define your fields once at the top of a blueprint and place them in tabs and columns by name.

Sections are gone: lists of pages and files are regular fields now and can be placed next to other fields with `width`, like everything else in your form. Your existing blueprints keep working, because Kirby converts their sections into fields automatically.

----

Intro:

Kirby 6 flattens your blueprints. Fields can be defined once and placed anywhere in the layout, sections have become fields, and the old blueprint presets are gone.

----

Example:

```yaml "/site/blueprints/pages/blog.yml"
title: Blog

fields:
  intro:
    type: textarea
  cover:
    type: filepicker
  articles:
    type: pagelist
    blueprints: article
    layout: table
    search: true

columns:
  - width: 2/3
    fields:
      - intro
      - articles
  - width: 1/3
    fields:
      - cover
```

## Define fields once, place them anywhere

Deeply nested tabs, columns and sections made blueprints hard to read and painful to rearrange. In Kirby 6, you can define all fields at the root level of a blueprint and reference them by name in your layout. Moving a field to another column or tab becomes a one-line change.

**Kirby 5**

```yaml "/site/blueprints/pages/blog.yml"
title: Blog

tabs:
  content:
    label: Content
    columns:
      - width: 2/3
        sections:
          content:
            type: fields
            fields:
              intro:
                type: textarea
          articles:
            type: pages
            headline: Articles
            template: article
            layout: table
      - width: 1/3
        sections:
          meta:
            type: fields
            fields:
              cover:
                type: files
                max: 1
          gallery:
            type: files
            headline: Gallery
            layout: cards
  seo:
    label: SEO
    fields:
      seoTitle:
        label: SEO title
        type: text
      seoDescription:
        label: SEO description
        type: textarea
```

**Kirby 6**

```yaml "/site/blueprints/pages/blog.yml"
title: Blog

fields:
  intro:
    type: textarea
  articles:
    label: Articles
    type: pagelist
    blueprints: article
    layout: table
  cover:
    type: filepicker
    max: 1
  gallery:
    label: Gallery
    type: filelist
    layout: cards
  seoTitle:
    label: SEO title
    type: text
  seoDescription:
    label: SEO description
    type: textarea

tabs:
  content:
    label: Content
    columns:
      - width: 2/3
        fields:
          - intro
          - articles
      - width: 1/3
        fields:
          - cover
          - gallery
  seo:
    label: SEO
    fields:
      - seoTitle
      - seoDescription
```

Both blueprints result in the same layout in the Panel. Kirby 6 still understands the Kirby 5 version, so you don't have to rewrite blueprints that work.

Read more in the (link: docs/guide/blueprints/layout#define-fields-once-place-them-anywhere text: layout guide).


## Sections become fields

Until now, blueprints had two building blocks: fields, which store content, and sections, which show lists of pages or files, info boxes and stats. In Kirby 6, fields fully replace sections. Blueprints only need fields, and lists of pages and files can be placed and configured like any other field.

| Kirby 5 section | Kirby 6 field |
| - | - |
| `type: pages` | `type: pagelist` |
| `type: files` | `type: filelist` |
| `type: info` | `type: info` |
| `type: stats` | `type: stats` |

The picker fields got new names along the way: `pagepicker`, `filepicker` and `userpicker`. `pages`, `files` and `users` are deprecated aliases for them.

Like sections before, the `pagelist`, `filelist`, `info` and `stats` fields don't have a value. They never store anything in your content files.

Existing blueprints keep working in Kirby 6 and are converted on the fly.

The (link: docs/guide/updates/update-to-v6/site-developers#blueprints__sections-become-fields text: guide for site developers) explains what the automatic conversion can't handle and how to rewrite a blueprint by hand.

## Blueprint presets have been removed

The `preset: page`, `preset: pages` and `preset: files` blueprint presets have been removed. They were a shortcut for simple layouts. With root-level fields and the new list fields, writing out the full blueprint is just as short and much easier to adjust later. See the (link: docs/guide/updates/update-to-v6/site-developers#blueprints__blueprint-presets text: guide for site developers) for details.

## Option fields

The `checkboxes`, `color`, `multiselect`, `radio`, `select`, `tags` and `toggles` fields have been rebuilt. Queries and API calls now go directly into their `options` option, and values that don't match any of the options are no longer removed. Read more about (link: docs/reference/panel/fields/select#dynamic-options text: dynamic options) and the (link: docs/guide/updates/update-to-v6/site-developers#blueprints__option-fields-query-and-api-move-into-options text: changes for site developers).

## Faster blueprints

Kirby 5 processed a blueprint again for every page, file or user that used it. Kirby 6 normalizes each blueprint only once per request and shares the result between all models with the same blueprint. Lists with many entries and views with many models benefit the most.
